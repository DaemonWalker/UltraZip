# Bandizip 功能盘点 & UltraZip 复刻对照

> 目的：把 Bandizip 拆成可落地的模块清单，对照 UltraZip 现状给出差距、优先级和架构影响。
>
> 依据：Bandizip 官网 [产品概览](https://www.bandizip.dev/product/)、[核心功能](https://www.bandizip.dev/product/features/)、[支持格式](https://www.bandizip.dev/product/formats/)、[专业版功能](https://www.bandizip.dev/product/pro/)、[版本对比](https://www.bandizip.dev/product/compare/)、[帮助中心](https://www.bandizip.dev/help/)。标注「界面行为」的条目来自桌面版实际交互，官网未逐条列出，动手前建议实机核对一遍。

## 0. 一句话结论

Bandizip = **压缩创建 + 解压 + 归档管理 + 系统集成** 四件事，每件都做到"日常够顺手"。
UltraZip 已覆盖**解压**与**压缩创建**两条纵线，解压侧尤其擅长"难例"（分卷 / 加密 / 拼接 ZIP / 伪装文件）；常规解压的顺手程度、归档管理和系统集成仍是主要差距。

所以"复刻 Bandizip"不是一个功能增量，而是**产品形态变更**：

- 现在：单窗口 → 拖入 → 一键解压（一次性 `7z x` 流水线）。
- Bandizip：归档浏览器 → 打开、浏览、挑着解、改、测、修、再打包（常驻会话 + 多次随机访问）。

复刻前必须先定范围。**范围已定：加入压缩创建**——实现方案见 §4.5，原「只解压不做压缩」的约定随之作废；归档浏览、包内编辑、Shell 集成仍按 §5 推进。

## 2. 功能全景

### 2.1 格式矩阵

- **可创建**：ZIP、7Z、ZIPX、EXE（自解压）、TAR、TGZ、LZH、ISO、GZ、XZ
- **可打开 / 解压（40+）**：ZIP、RAR / RAR5、7Z、ZIPX、TAR、ISO、GZ、XZ、ALZ、EGG、BR、ZSTD 等；另有 CAB、WIM、ARJ、LZH、J2J、Z、LZMA、BH 等历史格式（官网只写"40+"，逐项以实机"打开"对话框为准）

三个要点：

1. **创建格式 < 解压格式**。RAR 只能解不能建（UnRAR 源码许可限制，见 §6）。
2. **ZIPX / ALZ / EGG** 是 Bandizip 的地盘（WinZip 扩展方法、韩系格式），别的工具支持很差，属于"护城河"级兼容点。
3. 分卷命名：ZIP 为 `.z01/.z02/…/.zip`，7Z 为 `.7z.001/.002`。

### 2.2 压缩创建（UltraZip 已实现核心能力 → 参数方案见 §4.5）

| 能力 | 说明 | 7z 参数 |
|---|---|---|
| 压缩级别 | 存储 / 最快 / 快 / 普通 / 慢；7z 另可选算法、字典大小 | `-mx` `-m0` `-md` |
| 多核 | 按核数并行，版本限线程上限 | `-mmt` |
| 分卷 | 预设（CD、FAT32、邮件附件）或自定义 KB / MB / GB | `-v` |
| 加密 | 7Z：AES-256，可选加密文件名；ZIP：AES-256（会提示接收方兼容性） | `-p` `-mhe=on` `-mem=AES256` |
| 过滤 | 排除文件 / 目录、通配符 | `-x!` `-xr!` |
| 自解压 | EXE / SFX | `-sfx` |
| 完成后动作 | 测试、删除源文件、打开目录 | `t` / 自身逻辑 |
| 右键入口 | "压缩为 xxx.zip"、"添加到 xxx.7z" | `a` / `u` |

> 本表是 Bandizip 的能力面；UltraZip 的取舍、完整参数映射和三个必踩的坑见 **§4.5**。

### 2.3 解压（UltraZip 的主战场）

| 能力 | 说明 | UltraZip |
|---|---|---|
| 智能解压 | 单文件 / 单层目录时自动去掉多余嵌套目录 | ✗ |
| 三档目标语义 | 解压到当前 / 解压到 `<名>\` / 解压到… | ◐ 只有"解压到" |
| 部分解压 | 只解选中条目 | ✗ |
| 分卷归并 + 缺卷提示 | 从任意一卷进入，缺卷明确报出 | ✓（做得很扎实） |
| 密码 | 手输 / 记住 / 密码库 | ✓（还多了自动尝试） |
| 文件名编码 | 自动检测 + 手动指定代码页 | ✗ |
| 冲突策略 | 覆盖 / 跳过 / 自动重命名 / 逐个询问 | ✗（固定 `-y` 覆盖） |
| 元数据 | 保留时间戳、属性 | 由 7z 默认处理 |
| 拖出解压 | 从列表拖到资源管理器 | ✗ |
| 损坏包容错 | 修复后尽量取出可用数据 | ✗ |
| 进度 | 百分比 + 速度 + 剩余时间 + 当前文件 + 取消 | ◐ 有 % 与文件名、取消 |
| 结果清单 | 成功 / 失败条目列表、错误详情 | ◐ 只有错误摘要 |

### 2.4 归档浏览与管理（Bandizip 的灵魂）

- 双击压缩包进入"资源管理器式"窗口：树形目录 + 明细列表（名称 / 大小 / 压缩后大小 / 修改时间 / CRC / 属性 / 方法），状态栏统计（条目数、原始大小、压缩率）。
- **包内直接操作**：添加、删除、重命名、新建文件夹 —— 不必完整解压再重打包。
- **不解压直接查看 / 打开**：把单条目解到临时目录交给默认程序（图片、文本、PDF）。
- **包内图片预览**（Pro）：缩略图网格。
- 注释查看 / 编辑、属性页、包内查找（文件名）。
- 拖放：从资源管理器拖入 = 添加；从列表拖出 = 解压。

### 2.5 工具集

| 工具 | 说明 | 版本 |
|---|---|---|
| 完整性测试 | 遍历条目校验 CRC，输出坏条目 | 全版本 |
| 修复压缩包 | 扫描损坏 ZIP，重建中央目录、抢救可读数据 | Pro |
| 密码管理器 | 保存常用密码，压缩 / 解压时调用 | Pro（Std 有限） |
| 密码恢复 | 字典 / 暴力 / 掩码尝试，耗时不可控 | Pro |
| 安全扫描 | 解压前检查潜在恶意内容（引擎未公开） | Pro |

### 2.6 系统集成

- 资源管理器右键菜单：解压到当前文件夹 / 解压到 `<名>\` / 解压到… / 用 Bandizip 打开 / 压缩为…
- 文件关联（安装版）；便携版不写关联。
- Explorer 预览窗格（部分版本）。
- 命令行 `bz.exe`（随安装目录提供，支持 c / x / l / t 等子命令）——「界面行为」。
- 多语言（简繁中 / 英 / 韩 / 日等）、高 DPI、深色主题。

### 2.7 体验细节

- 大包打开速度靠列表懒加载（先读中央目录，按需解压单条目）。
- 设置中心：代码页策略、临时目录、覆盖策略、双击行为、关联、右键菜单项、更新。
- 写文件走"临时文件 → 校验 → 替换"，中断不留半成品（UltraZip 的 `ZipAesEngine` 已经是这个套路）。

## 4. 架构影响

### 4.1 从"一次性命令"到"归档会话"

浏览、部分解压、预览、拖出、包内编辑都要求同一个东西：**打开一次，多次随机访问**。当前 `SevenZipEngine.ExtractAsync` 是"一条 `7z x` 跑完走人"，没有会话概念。需要引入：

```
ArchiveSession
  ├─ ListEntries()            // 7z l -slt，常驻内存
  ├─ ReadEntryStream(path)    // 7z x -so 单流式读取（预览 / 查看用）
  ├─ Extract(paths[], opts)   // 7z x 带条目过滤
  ├─ Test(callback)           // 7z t，逐条进度
  ├─ Add / Delete / Rename    // 7z a / d / rn
  └─ Dispose()
```

好消息：这些都能继续用 7z CLI 实现，不违背"不换托管解压库"的约定。

### 4.2 7z CLI 的能力边界

| 需求 | 7z 支持 | 代价 |
|---|---|---|
| 列举条目 | `l -slt` | 大包每次全量解析中央目录，需缓存 |
| 选择性解压 | `x arch -o<dir> file1 file2` | 路径匹配要对齐 7z 的条目命名 |
| 流式读取单条目 | `x arch -so file` | 无随机 seek，预览大文件要限长 |
| 完整性测试 | `t` | 输出解析同进度逻辑 |
| 添加 / 删除 / 重命名 | `a` / `d` / `rn` | **整体重写归档**，不是真增量；大包代价高 |
| 压缩创建 | `a -t7z/-tzip -mx -p -mhe -v` | 分卷、加密、级别都能覆盖 |
| 修复 | 无 | 必须自己写（ZIP 层） |
| 密码恢复 | 无 | 必须自己写（校验循环） |

### 4.3 现有代码可复用的地方

- `ZipAesEngine` 的 EOCD / 偏移修正 / AES-CTR / HMAC 校验 → 直接是**修复**和**密码恢复**的地基。
- `PolyglotScanner` 的魔数扫描 → 修复时的本地头扫描可复用。
- `FormatDetector` 的分卷归并 → Shell 右键菜单"从任意卷进入"可直接复用。
- `PasswordVault` → 压缩创建时的"用库中密码加密"顺手就能接上。

### 4.4 产品形态分叉

| 形态 | 特征 | 影响 |
|---|---|---|
| A. 保持"一步式解压器" | 拖入 → 解压，主界面不变 | 只补 §2.3 的缺失项，工作量小 |
| B. 改成"归档浏览器" | 主界面变列表 + 工具栏 + 树 | 主窗口重写，工作量最大，但这才是 Bandizip 的形态 |
| C. 双模式 | 拖入即解压（默认），"打开"进浏览器 | 兼顾，但要维护两套交互 |

### 4.5 压缩创建：引擎与参数

**目标范围**（7z CLI 能力 ∩ UltraZip 定位）：

| 创建格式 | 7z 类型开关 | 说明 |
|---|---|---|
| 7Z | `-t7z` | 默认；固实、加密文件名、AES-256 |
| ZIP | `-tzip` | 兼容优先；Deflate / Deflate64 / BZip2，AES-256 |
| TAR | `-ttar` | 纯打包，不压缩 |
| GZ / BZ2 / XZ | `-tgzip` / `-tbzip2` / `-txz` | 单文件；多文件需先 TAR |
| TGZ / TBZ2 / TXZ | TAR → 压缩两步 | 组合格式，实现上串两次 |
| EXE（SFX） | `-sfx` | 需随包分发 `tools/7z/7z.sfx` |

不做：RAR（许可，见 §7）、ZIPX / ALZ / EGG（7z 不支持）、ISO / WIM / LZH（收益低）。

**参数映射**：

| UI 选项 | 7z 参数 | 备注 |
|---|---|---|
| 级别 存储 / 最快 / 快 / 标准 / 最大 / 极限 | `-mx=0/1/3/5/7/9` | ZIP、7z 默认都是 5 |
| 线程 | `-mmt=on` 或 `-mmt=<n>` | 默认 on，按核数 |
| 7z 方法 | `-m0=LZMA2`（默认）/ `LZMA` / `PPMd` / `BZip2` / `Copy` | Copy = 仅打包 |
| 字典 | `-md=16m/64m/256m` | 越大越慢越吃内存 |
| 固实块 | `-ms=on` / `-ms=64m` / `-ms=off` | 频繁增量更新的包建议 off |
| ZIP 方法 | `-mm=Deflate`（默认）/ `Deflate64` / `BZip2` / `Copy` | |
| 密码 | `-p"<密码>"` | 空密码时不传该参数 |
| 7z 加密文件名 | `-mhe=on` | 只对 7z 有效，必须同时有 `-p` |
| ZIP AES-256 | `-mem=AES256` | 配合 `-p`；WinRAR 可读，资源管理器不可读 |
| 分卷 | `-v<大小>`，如 `-v100m`、`-v4480m` | 单位 b / k / m / g |
| 排除 | `-x!*.tmp`、`-xr!node_modules` | `r` 前缀 = 递归 |
| 源列表 | `@listfile` 或多参数 | 源很多时用列表文件避免命令行超长 |
| 自解压 | `-sfx` | 输出 `.exe` |
| 进度 / 错误 | `-bsp1 -bso1 -bse1 -sccUTF-8 -y` | 与解压复用同一套解析 |

**三个必须处理的坑**：

1. **`7z a` 对已存在的包是「追加 / 更新」而不是「新建」**。目标已存在时必须先删（或拒绝并让用户改路径），否则新文件会混进旧包，用户以为覆盖了、实际是合并。
2. **取消会留下半个包**。解压失败只是留垃圾文件；压缩失败留下的是**看起来能用、实际缺条目**的包，危害更大。做法：先写 `<dest>.tmp`（分卷则写 `%TEMP%\UltraZip\pack_<guid>\`），成功后跑一次 `t` 校验，再改名/移动到位；失败或取消就整个删掉。
3. **7z 做不出 WinRAR 兼容的 `.z01` 分卷**。`-v` 对所有格式一律产出 `foo.zip.001/.002`。7z 格式无所谓（本来就是这命名），ZIP 则和 Bandizip / WinRAR 的 `.z01` 不兼容——要么接受 `.001` 风格并在 UI 写清楚，要么自己实现 ZIP 分卷写入（解压端也得配套）。**建议先接受 `.001`**。

**与解压的不对称点**：

| 差异 | 影响 |
|---|---|
| 源是多个文件 / 目录 / 通配符 | UI 需要源列表管理器（增删、排序、排除） |
| 目标格式由用户选 | `FormatDetector` 不参与 |
| 密码是「设置」而非「尝试」 | 复用 `PasswordVault`，但要提示「忘记无法恢复」 |
| 失败清理更关键 | 见坑 2 |
| 输出体积事先不可知 | 进度只能按「已处理 / 总字节」，可省略剩余时间 |

**引擎接口**：

```csharp
Task<ExtractResult> CreateAsync(
    IReadOnlyList<string> sources,
    string destPath,
    CreateOptions options,          // 格式 / 级别 / 方法 / 字典 / 密码 / 分卷 / 排除
    IProgress<ExtractProgress>? progress,
    CancellationToken ct);
```

参数拼装单独抽 `BuildCreateArgs(...)`，便于沿用现有「临时 console 工程跑断言」的方式做冒烟测试。

**验收**：

- 建 4 GB 分卷加密 7z，用 UltraZip 与 7-Zip 各解一遍
- 建 ZIP（Deflate + AES-256），WinRAR / 7-Zip 能开，资源管理器不能（预期）
- 压缩中途取消后目录无残留、无半成品
- 目标已存在时按「覆盖 / 取消」语义正确处理

**实际落地**：`CreateFormat / CreateOptions / CreateResult` 与 `SevenZipEngine.CreateAsync / BuildCreateArgs` 已实现；工作目录取公共父目录，优先在 `%TEMP%\UltraZip` 暂存（权限拒绝时回退输出目录并排除暂存目录），`7z t` 成功后才发布，失败/取消清理。已支持 7Z、ZIP、TAR、GZ、BZ2、XZ、TGZ、TBZ2、TXZ；ZIP 密码使用 AES-256，7Z 可加密文件名，ZIP 分卷采用 `.zip.001`。SFX 未做（仓库没有 `7z.sfx`），RAR/ZIPX/ALZ/EGG 不做。小包、加密分卷、取消和覆盖保护已实测；4 GB 大包尚未实测。

## 5. 分层路线图（粗估，按 1 人开发）

### P0 · 解压侧补齐（2–3 周）

- 归档条目列表窗口（只读）：树 + 明细列 + 统计栏
- 选择性解压（勾选条目）
- 智能解压（检测单层嵌套并压平）
- 冲突策略下拉（覆盖 / 跳过 / 重命名 / 询问）
- ZIP 文件名编码选择 + 自动检测（沿用密码编码穷举的思路）
- 完整性测试（`7z t`）
- 结果清单（成功 / 失败条目、耗时、平均速度）
- 进度补速度 / 剩余时间

**验收**：任意一个 1 GB 的 ZIP，能在 1 秒内列出条目；只解其中 3 个文件；同名文件按策略处理；坏包能定位到具体条目。

### P1 · 系统集成（1–2 周）

- 资源管理器右键菜单（级联 4 项：打开 / 解压到当前 / 解压到… / 测试；7-Zip 式静态注册表，见 [ui-and-shell-plan.md](ui-and-shell-plan.md) §2.2）
- 文件关联 + 单实例 + 命令行传参（`UltraZip.exe "x.zip"`）
- 从列表拖出解压
- 便携模式（不写注册表）

**验收**：右键任意 zip / 7z / rar 可用；`UltraZip.exe a.7z.002` 能自动找到首卷。

### P2 · 压缩创建 + 包内管理（3–5 周）

**压缩创建（先做，对应 §4.5）**

- `CreateArchiveDialog`：源列表（增删 / 排序 / 排除）、格式、级别、方法、字典、密码、分卷、输出路径
- `SevenZipEngine.CreateAsync`：参数拼装 + 进度解析 + 错误分类复用
- 覆盖语义（目标已存在先删）、取消清理（临时名 / 临时目录）
- 压缩后自动 `t` 校验并给结果清单
- 自解压（`-sfx`，需随包分发 `7z.sfx`）
- TAR→GZ/BZ2/XZ 组合格式

**包内管理**

- `ArchiveSession` 抽象落地
- 包内增 / 删 / 重命名（ZIP、7Z，重写式）

**验收**：建 4 GB 分卷加密 7z 能用 UltraZip 自己解开；建 ZIP（Deflate + AES-256）能被 7-Zip / WinRAR 正常打开；压缩中途取消后目录里无残留文件。

### P3 · Pro 工具（3–6 周）

- ZIP 修复（扫本地头重建中央目录，抢救可读条目）
- 密码恢复（字典 + 掩码，基于 ZipAesEngine 的校验器，先只支持 ZIP-AES / ZipCrypto）
- 包内图片预览（缩略图 + 大图）
- 安全扫描（可选：只做"危险扩展名提示"，不接外部引擎）

**验收**：手工破坏中央目录的 ZIP 能救回大部分文件；已知密码的包能在合理时间内命中。

### P4 · 打磨

主题、多语言、设置中心、Explorer 预览窗格、分卷大小预设、拖放排序、更新提示。

## 6. 决策点（动手前必须回答）

1. **范围**（已定）：加入压缩创建，方案见 §4.5。仍待定的是「做到多宽」——只做 7z / ZIP / TAR / GZ / BZ2 / XZ，还是追 ZIPX、LZH、ISO 创建（后者 7z 支持不全）。
2. **形态**：保持一步式解压器，还是改成归档浏览器为主界面（§4.4）。
3. **Shell 集成**（已定）：走 7-Zip 式静态注册表 verb，不做 COM、不做安装器，默认写 HKCU（详见 [ui-and-shell-plan.md](ui-and-shell-plan.md) §2.1）。
4. **Pro 工具**：修复 / 密码恢复 / 预览是否在范围内？密码恢复有被滥用的风险，建议限定「仅本机、仅用户自有包」。

## 7. 明确不建议复刻

| 项 | 原因 |
|---|---|
| 创建 RAR | UnRAR 源码许可禁止用于实现 RAR 压缩；只能调 `Rar.exe`（依赖本机装 WinRAR） |
| 广告位 / 商业授权 | 与开源/免费定位冲突 |
| 云端"安全扫描" | 需上传文件特征，隐私与合规成本高 |
| 40+ 格式全覆盖 | 收益递减；优先 ALZ / EGG / ISO / CAB / WIM 这几个真实场景多的 |
| macOS / 移动端 | 与 WPF 技术栈不兼容 |
